# Concepts

`nostromo` borrows its vocabulary from a certain spaceship. Here's the crew:

| Term             | What it is                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Manifest**     | A YAML file holding a tree of commands plus a few config settings. Lives in `~/.nostromo/ships/`. The core manifest is `manifest.yaml`.        |
| **Ship**         | Another name for a manifest — the `ships/` folder holds them all.                                                                             |
| **Spaceport**    | The set of docked manifests and the order they're loaded in. Stored in `~/.nostromo/spaceport.yaml`.                                          |
| **Command**      | A node in a manifest's command tree. It has an alias, an optional shell command (or code snippet), sub-commands and substitutions.            |
| **Keypath**      | A `.` delimited path to a command in the tree, e.g. `foo.bar.baz`. You run it as `foo bar baz`.                                              |
| **Substitution** | A short alias for a longer argument, attached to a command scope and swapped in at execution time.                                            |
| **Mode**         | How a command combines with its parents when executed: `concatenate` (default), `independent` or `exclusive`.                                |
| **Alias-only**   | A command that becomes a plain shell alias instead of a `nostromo` command.                                                                  |
| **Code snippet** | A `ruby`, `python`, `perl` or `js` one-liner run in place of a shell command.                                                                |
| **Dock / undock**| Add a manifest from a local or remote source to the spaceport, or remove it.                                                                 |
| **Sync**         | Re-download docked manifests from their sources when their version identifier changes.                                                       |
| **Detach**       | Slice a command subtree out of a manifest into a brand new manifest you can share.                                                            |
| **Cargo**        | The backups folder, `~/.nostromo/cargo`.                                                                                                    |

## The execution model

When you type `foo bar baz sls` in your shell:

1. The shell runs the `foo` function generated by `nostromo` (see [Shell integration](../getting-started/shell-integration.md)).
2. The function calls `nostromo eval foo bar baz sls`.
3. `nostromo` loads the spaceport, finds `foo` in the docked manifests and walks the keypath `foo.bar.baz`.
4. Along the way it collects each node's command according to its [mode](modes.md) and swaps any in-scope [substitutions](substitutions.md) (`sls` :material-arrow-right: `//some/long/string`).
5. The resulting command string is printed, and the shell function evaluates it in your current shell.

Everything `nostromo` knows is in the manifests, so you can always inspect exactly what will run with `nostromo eval ...` or `nostromo show --yaml`.
