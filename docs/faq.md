# FAQ and troubleshooting

## My new command isn't found

`nostromo` regenerates the shell functions every time a command changes, but only for the shell that ran the command. If you just installed `nostromo` or ran `nostromo init`, reload your shell:

```sh
source ~/.zshrc        # or ~/.bashrc
exec fish              # fish
. $PROFILE             # PowerShell
```

Then check that the wrapper and the command exist:

```sh
type nostromo          # should be a function, not just the binary
type foo               # "foo is a function"
```

If `nostromo` is *not* a function, the startup block is missing from your shell's init file — see [Shell integration](getting-started/shell-integration.md). Running `nostromo init` again adds it.

In other open terminals, or if you added the command from a different shell, run `nostromo init` or restart the terminal.

## `nostromo init` didn't touch my shell config

`init` only adds the startup block to init files that **already exist**: `.bashrc`, `.zshrc`, `~/.config/fish/config.fish` or your PowerShell `$PROFILE`. Create the file first, then re-run `nostromo init`.

## The command runs, but the arguments look wrong

Run the command through `eval` to see exactly what `nostromo` builds without executing it:

```sh
nostromo eval foo bar baz
```

Common causes:

- **Concatenate mode** joins the parent commands and *then* appends your arguments. If a parent command should not contribute to a child, give the child [`exclusive` mode](concepts/modes.md#exclusive) or use an empty parent command as a namespace.
- **`$1` placeholders** are replaced in order and the consumed arguments are removed; the rest are appended. See [Arguments](concepts/commands.md#arguments).
- **Substitutions** apply to every argument on the whole subtree. `nostromo find <text>` shows where a substitution is defined.
- **Quoting**: the command text is stored as-is and evaluated by your shell at run time, so `$(...)`, pipes and `&&` all work, but quote them when you `add` the command so *your* shell doesn't expand them first: `nostromo add cmd dock.rmi 'rmi $(docker images -q)'`.

## `command is disabled at <keypath>`

A command or one of its ancestors has `disabled: true` in the manifest. There's no CLI flag for this; edit `~/.nostromo/ships/<manifest>.yaml` and set it back to `false`, then run `nostromo init`.

## A command name clashes with a real program

A `nostromo` command named `code` shadows the `code` binary. Inside the command text, use the shell's `command` builtin to reach the real program:

```sh
nostromo add cmd code "command code"
```

Alternatively pick a different alias for the `nostromo` command.

## Completion doesn't work

Completion scripts are generated by `nostromo completion <shell>` and sourced from the startup block. Make sure:

1. `nostromo` is a function in your current shell (`type nostromo`).
2. For **zsh**, `compinit` has run — the block `nostromo` writes includes `autoload -U compinit; compinit`, but if you have your own completion setup make sure the `nostromo` block comes *after* it.
3. For **bash**, you're on bash 4+ with bash-completion installed (macOS ships bash 3.2 by default).
4. You've reloaded the shell after adding new commands.

## Where are my files?

Everything lives under `~/.nostromo` (or `$NOSTROMO_HOME`):

| Path                | Contents                                                   |
| ------------------- | ---------------------------------------------------------- |
| `ships/*.yaml`      | Manifests; `manifest.yaml` is yours, others are docked      |
| `spaceport.yaml`    | Docked manifest order and theme                             |
| `cargo/`            | Timestamped [backups](concepts/backups.md)                  |
| `man/`              | Generated man pages                                         |
| `downloads/`        | Temporary `dock`/`sync` downloads (only kept with `-k`)     |

`nostromo show -y` prints the merged manifests as YAML; `nostromo show -t` prints the command tree.

## I broke my manifest

Restore the latest backup from `~/.nostromo/cargo/`:

```sh
ls -t ~/.nostromo/cargo/manifest_*.yaml | head -1
cp ~/.nostromo/cargo/manifest_<timestamp>.yaml ~/.nostromo/ships/manifest.yaml
nostromo init
```

## How do I start over?

```sh
nostromo destroy       # recreate an empty core manifest, keep docked manifests
nostromo destroy -n    # nuke the whole ~/.nostromo folder
```

Neither removes the startup block from your shell init file — delete the lines between `# nostromo [section begin]` and `# nostromo [section end]` by hand if you're uninstalling for good.

## `sync` says nothing changed but the upstream file is different

`sync` compares the `version.uuid` of the downloaded manifest with your local copy and skips it when they match. If the publisher edited the file by hand without running `nostromo uuidgen`, force the update:

```sh
nostromo sync -f <name>
```

## Can I use `nostromo` from scripts or CI?

Yes. `nostromo eval <keypath> [args...]` prints the resolved command line to stdout, so scripts can do:

```sh
eval "$(nostromo eval deploy prod)"
```

Set `NOSTROMO_HOME` to point at a checked-in manifest folder to make this reproducible.

## Does `nostromo` run on Windows?

The binary builds and runs on Windows and PowerShell is a supported shell for completions and generated functions. Man pages aren't linked on Windows. Code snippets and command text are still executed by the shell you're in, so write them accordingly.

## Something else?

Run any command with `-v` for verbose output, then [open an issue](https://github.com/pokanop/nostromo/issues) with the output of `nostromo version` and `nostromo show`.
